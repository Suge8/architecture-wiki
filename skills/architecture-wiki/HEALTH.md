# 体检：health.md 产出规范

体检是首建的标配内容步骤，产出 `wiki/health.md`（再生页）与节点健康标记。事实全部来自确定性命令，你只解读与归位——页面上不出现无命令出处的论断。verify 打出"体检报告落后 N 个提交"时，在同步会话按本文重跑。

## 命令（写死，不开配置口）

1. **死代码/循环依赖**：按 [LANGUAGES.md](./LANGUAGES.md) 体检表跑对应语言命令（命令原文以表为准，钉主版本：跨大版本 CLI 会变，@latest 会让体检静默变行为）；退出码非零 = 有发现，不是失败。
2. **高危热点**：零依赖 git 管道——`git log --since="12 months ago" --name-only --pretty=format: | sort | uniq -c | sort -rn` 得每文件 churn，乘以当前行数（`wc -l`），取乘积前 10（或到明显断层处）且仍存在的源码文件。
3. **断点**：JS/TS 取 code-map 输出的 `error`（解析失败）与 `unresolved`（悬空相对导入）；其他语言为读码时确认的悬空引用，逐条注明出处。盲区如实注明：模板字符串动态导入对静态解析不可见（不进 imports 也不进 unresolved），靠死文件复核与工人边界回报兜底，断点小节末尾固定带一句此说明。

## 防误报复核（死文件上墙前必做）

knip 报的每个未使用文件，用文件名与去扩展名基础名全仓库搜字符串引用（`rg -l`）。有痕迹 → 归入"疑似"小节并写明痕迹位置；干净 → 才进死代码正文。动态引用误报与真死文件在 knip 输出中同形，这道复核是死代码小节可信度的来源。

## 页面结构（固定）

frontmatter 写 `generated: <死代码命令原文>` 与 `generated-at: <当前 HEAD>`，不写 sources（verify 对再生页跳过哈希检查，只做落后提示）。正文四个 H2，标题逐字固定——HTML 警示标锚点依赖它们：

- `## 死代码`：确认条目，另加 `### 疑似（存在动态引用痕迹，需人工确认）`
- `## 循环依赖`：每条环列出完整路径
- `## 高危热点`：前 10 排名表（文件、12 个月改动次数、行数）
- `## 断点`：悬空引用与解析失败，逐条指回文件

每条事实配一句人话解读；某类命令跑不了时该节写"未运行（原因）"。health.md 链入 index.md 导航。

## 节点标记

health.md 条目按文件归属（模块页 covers）映射到 data.json 节点：命中的节点加 `health` 数组，值取 `dead`/`cycles`/`hotspot`/`breaks`（对应上面四节）。同时在 data.json 顶层填 `health` 计数对象（files=源文件数，dead/suspects/deadExports/cycles/breaks=工具输出的条目数），模板据此渲染体检页顶部的评分环与优化建议——评分公式（密度化）固化在模板，不手填分数。模板据此渲染楼顶与侧边栏警示标，点击跳体检页对应小节；无 health 字段的节点与仓库不显示任何体检痕迹。改动 health.md 或 health 字段后重渲染 HTML。
