# Fan-out 并行产页

并行的理由是上下文而不是速度：中型仓库上百个文件的 imports/exports/行数细节塞不进单个会话，编排者读完就没余量写页了。首建时拆成 orchestrator-worker 单波并行：每个工人只背自己那一个模块的上下文，编排者只保留全局视野做对账与总览页。工人彼此不可见，跨模块论断由你收口。

## 派工

按 code-map 输出切分模块（粒度按 SKILL.md：单页超 20 文件或 6000 行就复查职责能否一句话说清）后，给每个工人一张任务卡：

- 目标：产出一页完整的 `docs/architecture/wiki/modules/<name>.md`，含 sources 与 covers frontmatter（covers 即分配的路径范围）及 SKILL.md 规定的固定四节（职责、对外接口、数据怎么流、改动指南），直接写入该文件。
- 预置事实：该模块的文件清单及每个文件的 imports/exports/loc 摘要，从 code-map 输出切片粘入任务卡；工人从这里出发读码，不从零探索。
- 边界：读码限于分配文件及其一跳 import；只写自己那一页，页面文件互不重叠。
- 输出契约：正文每条论断指回具体文件；点名的每个 symbol 已确认存在于所引文件；每条 sources 行的哈希来自 `git hash-object` 实际运行结果。另外在返回消息末尾做边界回报：列出分配清单之外、但与本模块存在 import 关系的文件（文件 + 关系一句话），没有则写“无”；回报不写入页面。

任务卡不提渲染、lint 等后续步骤。所有工人同一波发出，任务之间无依赖，工人模型取编排者同级或低一档。

## 收口

工人全部返回后由你完成：

1. 对账：先消化各工人的边界回报——漏分配的文件补进某页 covers 或补页；再逐页核对——页面声称的依赖与导出和 code-map 图上的边一致、每条论断指回具体文件、深度撑得起模块职责一节。任何一项不过的页派新工人重写，任务卡附上原任务卡、原页面和具体差错。
2. 亲自写 index.md、system.md、data-flow.md——跨模块论断需要全局视野，不派工；对账时已通读模块页，直接下笔。
3. 回到 SKILL.md 步骤 3 做体检、步骤 4 跑 verify；报错页同样派新工人重写（返工永远是新工人，完成的工人收不到后续消息）。verify 通过即收口完成。
